# Лабораторная работа № 4 — Treponema pallidum

Итоговый Word-отчёт: [Andreev_Lab4_Treponema_Report.docx](deliverables/Andreev_Lab4_Treponema_Report.docx).
PDF для просмотра: [Andreev_Lab4_Treponema_Report.pdf](deliverables/Andreev_Lab4_Treponema_Report.pdf).

Отчёт построен по сохранённым измерениям `results/final/*.json`, графикам, полным исходным программам и двум скриншотам RuTube из предоставленного автором документа. Генератор отчёта **не запускает эксперименты и не выполняет сетевые запросы**. Числа для RuTube переписаны с исходного скриншота; сетевой доступ к RuTube при подготовке отчёта не требуется.

## Содержание комплекта

- Основное изображение трепонемы и дополнительные материалы: `data/raw/`, источники и лицензии в `sources.json`.
- Галерея из 80 фрагментов: `data/final_gallery/`.
- Набор из 40 вариантов шести видимых компонент: `data/final_pose/`.
- Измерения, изображения и веса двух YOLO-pose: `results/final/`.
- Два архива COCO и XML со скелетами: `results/final/cvat/`.
- Полные программы: `scripts/run_*.py`, общий модуль `experiment_common.py`.
- Манифест рисунков и полных листингов с SHA-256: `deliverables/report_manifest.json`.

Основной файл `data/raw/treponema_primary.jpg` соответствует [изображению из задания](https://pcr.news/upload/iblock/3a5/3a5ebdd65880badcc702e1bed5c07618.jpg). Это цветная иллюстрация; геометрия измеряется в пикселях. Палочковидные бактерии и кокки из `../lab4` используются как классы сравнения. Для них в отчёте явно указан сравнительный набор.

## Пересборка документа из готовых результатов

Из каталога `lab4_treponema`:

```bash
python scripts/build_submission.py
REPORT_ROOT="$PWD" \
REPORT_BASENAME=Andreev_Lab4_Treponema_Report \
REPORT_HEADING='Прикладные методы компьютерного зрения\nАнализ изображений Treponema pallidum' \
python ../lab4/scripts/render_report.py
python scripts/finalize_document.py
```

Требуются python-docx, Pillow и reportlab; для финальной пагинации — LibreOffice и pdftotext. Экспериментальные библиотеки для сборки самого отчёта не импортируются. Финализатор добавляет номера страниц в содержание и экспортирует PDF из DOCX с одинаковой пагинацией. Программа `report_content.py` вызывает тот же генератор блоков.

## Локальный запуск Streamlit в Windows

```powershell
python -m streamlit run scripts/app.py
```

Этот способ использует текущий Python и обходит устаревший путь внутри `streamlit.exe`. В интерфейсе укажите каталог вашего готового индекса `data/rutube/index`; он должен содержать `index.json`, `vectors.npy` и папку кадров. Ваш видеоролик и индекс остаются на компьютере, где выполнялся запуск. В репозитории сохранены исходные скриншоты результатов этого запуска.

Программа `rutube_download.py` предназначена для самостоятельного запуска. С аргументом `--local-video` она индексирует уже сохранённый файл. Не запускайте её для пересборки отчёта.

## Воспроизведение экспериментов

Полные программы и параметры находятся внутри соответствующих разделов DOCX. Для нового вычислительного запуска устанавливаются зависимости из `requirements.txt`, подготавливаются веса через `prepare_models.py` и маска через `prepare_primary.py`. Затем запускаются нужные `run_*.py`. Это отдельная операция, которая может загружать веса и изменять результаты; для чтения и пересборки отчёта она не нужна.

В Linux MediaPipe Tasks использует системную библиотеку `libGLESv2`. Tesseract устанавливается как системная программа с английским языковым пакетом. В окружении OpenCV должен оставаться один пакет contrib, чтобы были доступны `cv2.legacy`-трекеры. Архитектура RRDBNet находится в `../lab4/models/RRDBNet_arch.py` и полностью включена в отчёт.

Сохранённые результаты охватывают локальные опыты; архивы CVAT представлены как подготовленные для импорта. Полный программный сценарий дополнительных счётчиков находится в `run_video_checks.py`; численные результаты без сохранённых выходных файлов в отчёт не добавляются.
